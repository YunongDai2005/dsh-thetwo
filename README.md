# TheTwo

同一份会话。

多个 DSH 设备共享会话库。首次选择设备并由对方允许后，连通时自动同步完整回复，换个设备继续聊天。

**TheTwo 0.1.0** 使用 DSH 提供的会话、附件和界面服务，同一份插件可随宿主升级继续使用。插件清单没有 DSH 版本白名单。同步面向 DSH Session V4；遇到无法识别的会话格式会保留原记录。Windows 与 Mac 可在局域网内交替续聊，也支持通过可达的私网隧道连接。已有配对和会话会保留，API 密钥和插件共享由每台设备分别授权。

## 使用

1. 在需要共享会话的 DSH 设备上安装并启用 `dsh-thetwo`。
2. 在左侧 TheTwo 会话同步面板找到另一台电脑，点击「同步」，另一端点击「允许同步」。无需 PIN、扫码或额外账户。
   配对后，左侧 TheTwo 卡片下方每台设备是一个细胞，样子就是同步状态：正在同步（描边变亮，小泡在卡片和细胞之间往返）、已同步、有更新待处理（空心核）、已暂停（灰色空心核）、离线（灰色）；附近尚未配对的设备是虚线小细胞。点一下细胞可以打开设备设置、暂停或继续同步。
3. 默认每 5 秒检查新记录；完整回复结束后同步，正在生成的半条回复会等待。
4. 在共享会话库点「打开」。已经打开的会话收到新记录后，点「打开最新」即可续聊，无需重启 DSH。旧标签页保留；后续请从共享会话库进入最新版本。本机已归档的记录会标记，可选择「取消归档并打开」；归档状态不随会话传输。
5. 点击设备卡片上的「设置」，直接展开该设备；也可以在设置页的「已连接设备」中逐台展开。先设置设备名称，再选择该设备的同步内容，修改后点击「保存设备设置」。这里的名称仅在本机显示，留空使用设备原名。API 和插件共享默认关闭，普通会话同步无需开启它们。本机名称、自动同步、自动发现和检查间隔单独保存。暂停同步位于设备设置内，解除配对位于「连接管理」。

首次配对授权覆盖之后新增的可同步普通会话。解除配对会停止未来交换，不删除已收到的本机记录。

暂停、解除配对或关闭同步选项会取消相关在途请求和未提交操作；立即恢复也不会重新放行旧批次。已经保存的会话、密钥和已经交给 DSH 安装的插件保留。配对请求发送失败后可直接再次点击「同步」，不需要等待过期。

## 同步内容

| 内容 | 行为 |
| --- | --- |
| 普通会话 | 默认自动同步，保留消息、工具历史、事件次序和分支历史 |
| 图片、上传文件 | 默认随会话传输，校验并保存附件后才导入会话；每条会话合计最多 24 MiB、128 个附件 |
| API 密钥 | 每设备默认关闭；双方针对彼此开启后，仅补入 DSH 凭据服务中缺失的模型 API-key 记录，保留已有记录 |
| 第三方插件 | 每设备默认关闭；双方针对彼此开启后列出包名和精确版本，本机选择安装缺少的插件后交给 DSH 包管理器 |
| 模型配置、OAuth、环境变量、插件配置 | 留在本机 |
| 项目目录、删除/归档状态、内部子任务 | 不自动复制 |

API 密钥选项只处理 `llm-*` 所属的已保存 API-key 记录，不读取系统钥匙串、OAuth 授权、`.env` 或任意凭据。两端可继续使用各自不同的模型和密钥。插件仅共享注册表包及版本，不传本地路径、Git 源、官方内置包或 TheTwo 自身；已有版本保留，构建脚本审批继续由 DSH 处理。特殊插件可能要求重启 DSH。

## 同时续写与离线

不同设备从同一历史分别续写时，不覆盖或拼接内容。保存收到的各个完整分支，暂停原会话的合并；「查看其他版本」会将所有保存的副本恢复为可继续同步的会话，并打开其中一条，其余可在会话库中选择。已保存分支不重复下载，新设备的第三个分支也会保留。首次回传失败会重试，也能补齐旧版本只在一端保存冲突的记录。旧原生标签页里的独立续写同样保留。

离线设备只能使用此前收到的内容。未发送的更新需要两端再次在线后才能收到。

接收的完整检查点先写入本机待处理区，再导入 DSH。导入中断后重试会补齐会话、导入索引和共享工作区登记；已写入的历史不会重复追加。

DSH 对已打开会话保留独占写入权。TheTwo 使用受支持的持久化接口创建最新记录的本机续聊版本，并将共享会话 ID 映射到该版本；不关闭其他插件持有的 Agent、不修改正在运行的内存状态、不绕过写锁。因此原生 DSH 列表可能保留旧版本，共享会话库仍只展示一个当前入口。

## 网络

- 发现使用 UDP `48791` 广播和 `239.255.47.91` 组播；传输使用 TCP `48792`，占用时顺延到 `48807`。
- 同一可互通局域网内自动发现；不同 Wi-Fi 或相邻子网需要路由可达，自动发现还需要网络允许相应广播/组播。访客隔离或防火墙不能由插件自动穿透。
- 找不到设备时，展开备用入口，输入对方私网 IPv4 和端口。每台已配对设备记住最近连通过的几个地址（局域网、隧道各一个也可以），换网络后自动改用还能连通的那个；失效的地址几秒内让位，不拖慢其他设备。
- 通过隧道连接：使用 Tailscale、ZeroTier、WireGuard 等组网工具时，输入对方在隧道里的地址（如 `100.x.x.x:48792`）；使用 `ssh -L`、frp 等端口转发时，输入本机转发入口（如 `127.0.0.1:转发端口`）。只需要在能连过去的一端输入一次。
- 只有一个方向连得通也可以配对和同步，例如端口转发、一端防火墙挡住入站、虚拟机或 WSL 的 NAT。能连过去的一端发起配对，另一端点「允许同步」后，由发起端取回确认；之后会话由发起端负责收发，另一端显示「由对方连入」。此时 API 密钥和插件列表只有发起端能取到。
- 设备卡片显示「对方没有这台设备的配对记录」时（对方解除了配对，或上次配对没有完成），点「重新配对」，对方再次允许即可，这台设备的名称和设置会保留。
- DSH 重启后的头几分钟，如果另一台电脑的时间明显偏慢，它发来的请求会暂时被拒绝，时间对齐后自动恢复。两端时间差仍应小于 5 分钟。
- 慢隧道上的大会话可以传完：建立连接最多等 4 秒，连上之后只要数据还在传就不会超时，单次传输最长 10 分钟。接了连接却不通的转发入口、被别的设备占用的地址，几秒内就会被识别并跳过。
- 重启 DSH 后优先使用上次的监听端口，为它配置的隧道或端口转发不用重设；明确写出的端口（包括 `:80`）按原样使用。
- 仅支持私网 IPv4 传输；不需要云服务、NAS 或常开主机。两端系统时间差应小于 5 分钟。
- 不支持公网地址或域名直连：首次配对没有带外身份核对，不适合暴露在公网上。frp 等转发到公网入口的用法，需要对端能通过私网或本机地址访问该入口。
- 系统防火墙可能需要允许 DSH 的专用网络通信。插件不修改系统防火墙。
- X25519 + HKDF + AES-256-GCM 加密认证。首次配对依赖双方核对设备名称和地址并点击允许；没有带外身份验证，适用于可信局域网。

## 安装

在桌面 DSH 中打开「插件 → 添加插件 → 安装第三方插件」，输入 npm 包名 `dsh-thetwo`，安装后点击「立即启用」。离线安装时，从 [GitHub Releases](https://github.com/YunongDai2005/dsh-thetwo/releases) 下载 `dsh-thetwo-0.1.0.tgz`，在同一入口输入文件的本机绝对路径即可。

Web profile 可使用官方 CLI：

```powershell
dsh plugin --profile web add dsh-thetwo
```

桌面用户可在 DSH 插件管理器里卸载；Web profile 可运行 `dsh plugin --profile web remove dsh-thetwo`。已同步会话会保留。

数据位于 `$DSH_HOME/session-link/`，用于保持早期配对兼容性。`devices.json` 含本机私钥，不能将整个目录复制到另一台机器。新导入会话位于本机共享工作区；记录里的外机路径仅作为历史保留，不会据此执行或复制项目文件。

## 开发与验证

生产包只使用 Node 内置模块和 DSH 注入服务，React 由 DSH 提供；开发依赖不进入发布包。

```powershell
npm ci --ignore-scripts
npm run check
npm run test:all
npm pack --ignore-scripts --pack-destination artifacts
npm run verify:pack
npm run verify:install
```

自动测试使用隔离的真实 DSH 存储、Agent、附件及凭据服务和回环网络，模型由本地固定适配器返回，不消耗真实 API。`npm run preview` 启动独立 Web profile，地址由终端显示；默认关闭 LAN 发现。`DSH_TEST_NODE_MODULES` 可指定独立测试运行时。

目录按 DSH revision 缓存，未改变会话不重复解码；待应用检查点不会反复下载。传输仍使用完整检查点，单个加密消息最多 64 MiB，大于限制的记录单独显示原因，不影响其他会话。大附件分块、完整环境复制和大型历史库负载优化尚未实现。

各版本的验证范围见 [GitHub Releases](https://github.com/YunongDai2005/dsh-thetwo/releases)。数据约定见 [架构说明](https://github.com/YunongDai2005/dsh-thetwo/blob/main/ARCHITECTURE.md)。
